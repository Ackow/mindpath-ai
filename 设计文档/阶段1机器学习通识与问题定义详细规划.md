> 对齐《AI学习路线与知识地图》的 1.1-1.3。本阶段不追求掌握更多模型，而是建立正确的问题定义、指标选择和实验边界。完成后，学习者应能把一个业务需求写成可评估的机器学习任务，并为阶段 2 的监督学习选择合理基线。

## 1.1 机器学习问题地图

### 章节目标

能够区分学习范式和任务类型，并用统一的符号描述样本、特征、标签、模型、预测、损失与决策。重点是**先界定问题，再选择算法**：许多失败项目的根因是标签、预测时点或行动闭环定义错误，不是模型不够复杂。

### 1.1.1 何时适合使用机器学习

- 明确规则、计算或检索即可稳定解决的问题，优先使用规则、查询或传统软件；ML 并非默认答案。
- 适合 ML 的信号：存在历史样本或反馈、输入与目标之间有可学习规律、预测结果能够触发行动、错误成本可承受。
- 不适合直接上线的信号：标签不可得或严重滞后、数据不代表未来、目标本质是价值判断、自动化决策会造成不可接受的安全/公平/合规风险。
- 区分预测、因果推断、生成、检索、优化和决策：预测到“谁可能流失”不自动回答“给谁优惠能减少流失”。
- 将“模型准确”与“业务有效”分开：没有干预动作、执行资源或反馈闭环的预测通常不能产生价值。

**练习**：为“FAQ 回复”“欺诈拦截”“给用户发优惠券”“文档问答”四个需求判断首选方法，并逐项写出数据、反馈、错误成本和不使用 ML 的备选方案。

### 1.1.2 统一问题描述

对每个任务使用以下模板，不允许只写“做一个预测模型”：

| 字段 | 应回答的问题 | 分类示例 |
|---|---|---|
| 决策对象 | 一次预测对应谁或什么？ | 一个订单、一名用户、一次设备读数 |
| 预测时点 | 在何时、只能看到何时以前的信息？ | 下单确认前；不含退款结果 |
| 特征 `X` | 预测时真实可获得的输入是什么？ | 历史订单、设备传感器、文本特征 |
| 目标 `y` | 具体标签、观察窗口和标注规则？ | 30 天内是否退款 |
| 输出 | 分数、类别、排序还是生成内容？ | 欺诈概率 `p(y=1|X)` |
| 行动 | 输出如何影响决策？ | 人工复核、拦截、推荐、告警 |
| 成功标准 | 离线指标和线上业务指标分别是什么？ | PR-AUC；减少损失且控制复核量 |

- **样本单位**：一行是用户、用户-日期、订单还是会话；变化会改变标签、泄漏风险和切分方式。
- **观察窗口与预测窗口**：例如以第 0 天为预测时刻，使用 `[-90, 0]` 的行为预测 `(0, 30]` 的结果；未来窗口中的字段不可作为特征。
- **标签构造**：定义正负类、未知样本、延迟标签、人工标注一致性和标签噪声；标签是对业务现象的测量，不等于绝对事实。
- **特征可用性**：每一列标明来源、生成时刻、更新频率、是否允许线上取得和是否含个人/敏感信息。

### 1.1.3 学习范式

| 范式 | 数据与信号 | 典型任务 | 常见误解 |
|---|---|---|---|
| 监督学习 | `(X, y)` 成对样本 | 回归、分类、排序 | 有标签不代表标签质量足够 |
| 无监督学习 | 只有 `X` | 聚类、降维、异常发现 | 聚类编号不是天然业务人群 |
| 半监督/弱监督 | 少量、噪声或程序化标签 | 文本/图像标注扩展 | 伪标签会放大原有偏差 |
| 自监督学习 | 从数据自身构造预测目标 | 表示学习、预训练 | 预训练目标不等于下游目标 |
| 强化学习 | 状态、动作、奖励、延迟反馈 | 资源分配、控制 | 奖励设计错误会优化错目标 |

学习本阶段时只需能识别边界。阶段 2 首先以监督学习为主；聚类、PCA、推荐和强化学习分别在后续阶段深入。

### 1.1.4 任务类型与输出空间

- **回归**：目标为连续数值，如未来销量、房价、等待时长。关注 MAE/RMSE、分位数误差和误差的业务单位。
- **二分类**：目标为两类事件，如是否违约。模型最好输出概率/分数，阈值由行动成本决定。
- **多分类与多标签**：多分类每个样本通常一个互斥类别；多标签可同时属于多个类别，二者的编码、损失和评估不同。
- **排序/推荐**：目标是同一上下文中的相对顺序，离线指标通常是 Recall@K、NDCG；不能只把它当逐条二分类。
- **时间序列预测**：未来不可见，切分必须遵从时间；随机打乱通常造成乐观估计。
- **异常检测**：区分少见、噪声、新类别与真正异常；异常的业务定义、调查成本和反馈闭环更重要。
- **生成式任务**：需要定义事实性、安全性、风格、延迟与人工评估；自动指标通常不充分。

### 1.1.5 核心术语与关系

```text
业务问题 -> 样本单位/预测时点 -> 特征 X + 标签 y
        -> 模型 f_theta(X) -> 分数/预测 y_hat -> 阈值或排序
        -> 业务行动 -> 反馈与新数据
```

- `X` 是模型输入，`y` 是训练时目标，`y_hat` 是预测，`theta` 是从训练数据学习的参数。
- 损失函数用于训练时衡量单个或平均样本误差；评估指标用于选择模型、沟通效果；业务 KPI 衡量真实行动结果，三者可能不同。
- 参数由训练学习，超参数由训练过程前或验证集选择；不能通过测试集反复调参。
- 基线是必须击败的简单方案，如均值预测、众数预测、规则系统或当前人工流程。

2. 选一个业务例子，列出 5 个会造成时间穿越或标签泄漏的字段，并说明原因。

**验收**：给定一个自然语言需求，10 分钟内能产出完整问题描述，并说明为何该任务属于某一范式、哪一种简单方案应作为基线、哪些数据在预测时刻不可用。

## 1.2 业务目标转化

### 章节目标

把业务目标转换为可测量的标签、行动、指标和阈值。学习者应能解释“为什么这个指标适合当前决策”，而不是机械地报告 accuracy 或 RMSE。

### 1.2.1 从目标到决策闭环

按以下顺序写问题定义：

1. **业务目标**：例如减少欺诈损失、提升人工审核效率、缩短等待时间；要求可观测且有时间范围。
2. **决策与资源约束**：模型输出后谁采取何种行动，每天最多处理多少样本，延迟、预算和人工能力是多少。
3. **标签/代理目标**：真实目标不可立即观测时，说明代理标签的偏差，如“投诉”并不等于“不满意”。
4. **模型输出和阈值**：需要概率、分数、类别或排序；阈值由预期收益、容量、风险和政策决定。
5. **离线指标与线上 KPI**：离线指标用于筛选候选方案，线上 KPI 或受控实验验证业务影响。
6. **约束指标**：公平性、召回底线、人工复核量、延迟、稳定性和合规要求不能被单一主指标掩盖。

### 1.2.2 标签设计与数据可行性

- 明确正例、负例和未知样本；不要把未观察到事件简单当成负例而不检查观察期是否完整。
- 标注规则应可被他人复现：标注人、规则版本、冲突处理、抽检方法和一致性指标要记录。
- 检查标签滞后：预测“30 天内是否违约”至少要等 30 天才能得到完整标签，训练数据的截止日期应早于该窗口。
- 处理选择偏差：只有被人工审核的订单才有“是否欺诈”标签时，标签分布并不代表全部订单。
- 区分相关特征与可行动特征；模型可以使用历史行为预测，但不应以此宣称某个干预一定有效。

### 1.2.3 分类指标、阈值与代价

混淆矩阵的四种结果：TP、FP、TN、FN。先说明哪一种错误危害更大，再选择指标。

| 场景 | 主要风险 | 先看指标 | 常见补充 |
|---|---|---|---|
| 疾病初筛/安全告警 | 漏掉正例（FN） | Recall、PR 曲线 | Precision、人工复核容量 |
| 垃圾邮件/自动拦截 | 错伤正常样本（FP） | Precision | Recall、用户申诉率 |
| 极不平衡欺诈 | accuracy 虚高 | PR-AUC、Recall@固定容量 | 校准、预期成本 |
| 多类别分类 | 小类被忽略 | macro F1、每类 recall | 混淆矩阵、加权平均 |
| 排序/推荐 | 前 K 位价值 | Recall@K、NDCG@K | 覆盖率、多样性、线上 CTR |

- `precision = TP / (TP + FP)`：被模型判为正的对象中，有多少是真的正。
- `recall = TP / (TP + FN)`：真实正例中找回了多少。
- F1 是 precision 与 recall 的调和平均；当两种错误的代价不对称时，不能用 F1 自动替代成本分析。
- ROC-AUC 反映不同阈值下的排序区分能力；在正例稀少时应同时查看 PR-AUC 和具体工作点。
- 模型分数不是天然可信概率。若行动依赖概率或成本阈值，检查校准曲线和 Brier score。
- 阈值应在验证集或交叉验证结果上预先确定；测试集只做一次最终评估。

### 1.2.4 回归指标与不确定性

- MAE 的单位与目标相同，较易沟通；RMSE 更惩罚大误差，但容易被极端值支配。
- 先看残差分布、分组误差和分位数误差；一个平均指标可能掩盖某些人群或高价值样本的系统性失败。
- `R^2` 是相对基线的解释度，不表示预测百分比准确，也不保证外推可靠。
- 当不确定性影响决策时，考虑预测区间或分位数预测；报告它们的覆盖率，不只报告区间宽度。
- 每个指标都附带抽样不确定性：使用 bootstrap 或适合的置信区间，对相近模型避免过度解读微小差异。

### 1.2.5 代价敏感决策

- 写出 TP、FP、TN、FN 的收益/代价或优先级，即使开始时只能是区间估计。
- 对二分类分数 `p`，比较“采取行动”和“不采取行动”的期望收益；阈值来自二者交点及容量约束，而不是默认 0.5。
- 资源有限时优先讨论 top-K 选择、排序质量和每个行动带来的边际价值。
- 公平性需要明确受保护群体、测量方式、合法性和权衡；不能只删掉敏感字段，因为代理变量仍可能存在。

### 1.2.6 章节练习与验收

1. 为“每天最多人工审核 100 笔交易”的场景写出决策表，选择主指标和阈值选择法。
2. 为“预测下周需求”选择 MAE 或 RMSE，并用业务损失解释取舍。
3. 从一个公开数据集中写出标签定义、观察窗口、三项特征可用性检查和一个潜在偏差。
4. 对两个 AUC 相近的模型，使用 bootstrap 区间判断差异是否值得投入工程成本。

**验收**：能给出一页“指标契约”：业务目标、决策动作、主/约束指标、阈值策略、评估切分、基线、错误代价和停止条件。评审者可据此复现指标计算而无需猜测。

**参考资料**

- [scikit-learn: Model evaluation](https://scikit-learn.org/stable/modules/model_evaluation.html)：所有指标的定义、适用条件和 API。
- [scikit-learn: Probability calibration](https://scikit-learn.org/stable/modules/calibration.html)：理解概率输出和校准曲线。
- [Google Rules of ML](https://developers.google.com/machine-learning/guides/rules-of-ml)：阅读“先定义指标、先建立基线、避免管道复杂化”的实践原则。
- [Fairlearn documentation](https://fairlearn.org/main/user_guide/index.html)：了解公平性评估的术语与限制，不将单一数值视为合规结论。

## 1.3 端到端 ML 流程

### 章节目标

建立从问题定义到迭代的标准闭环，并明确每一步的输入、输出、质量闸门与常见失败模式。此章节不训练复杂模型，首选 dummy 和线性模型来验证流程正确性。

### 1.3.1 标准流程与质量闸门

```text
需求/指标契约
  -> 数据审计与标签定义
  -> 切分策略
  -> 可复现 baseline
  -> 训练与验证
  -> 一次性测试集评估
  -> 错误/分组分析
  -> 上线或下一轮假设
```

| 步骤 | 输入 | 核心动作 | 质量闸门 | 输出 |
|---|---|---|---|---|
| 问题定义 | 业务需求 | 定义样本、时点、标签、行动和指标 | 指标契约经确认 | problem brief |
| 数据审计 | 原始数据 | schema、缺失、重复、分布、标签质量 | 数据字典与风险清单齐全 | EDA 报告 |
| 数据切分 | 带时点/群组的数据 | 随机、分层、分组或时间切分 | 无未来信息、无实体重叠 | 固定 split |
| 基线 | 训练集 | dummy、规则、线性模型 | 可复现且胜过/量化现状 | baseline 指标 |
| 验证迭代 | 训练/验证集 | Pipeline、CV、调参、记录 | 不接触测试集 | 候选模型 |
| 最终评估 | 冻结模型 + 测试集 | 主指标、约束指标、区间、分组 | 测试集只评一次 | 评估报告 |
| 误差分析 | 预测与原始字段 | 分组、抽样、根因假设 | 区分证据与猜测 | 迭代 backlog |

### 1.3.2 数据切分策略

- **随机切分**：样本近似独立同分布时使用；分类任务常用分层切分以保持类别比例。
- **分组切分**：同一用户、病人、设备、文档或家庭的多条记录必须进入同一侧，避免实体记忆造成虚高。
- **时间切分**：预测未来时按时间训练、验证、测试；特别检查特征是否在预测时刻可得。
- **交叉验证**：用于训练集内稳定估计和选择超参数；它不替代最终留出测试集。
- **测试集冻结**：确定问题、特征和超参数前不查看测试指标；反复测试即间接把测试集变成验证集。

### 1.3.3 基线与实验设计

- 先运行 `DummyClassifier`/`DummyRegressor`，得到类别比例、均值或中位数基准。
- 再建立解释性强的线性或简单树模型；复杂模型只有在改善幅度、成本、延迟和维护复杂度合理时才值得采用。
- 一次实验只改变一个明确假设，例如“中位数填补是否比删除缺失列改善召回”；记录其余配置不变。
- 固定 seed、数据版本、切分索引、特征列表、代码 commit 和依赖版本；差异必须可追溯。
- 将调参预算写入实验计划，例如只对 2 个模型和有限网格做 CV；避免无限试错造成验证集过拟合。

### 1.3.4 错误分析与迭代

- 将错误按真实类、预测类、置信度、关键人群、时间段、数据来源和缺失模式分组。
- 优先核查高置信度错误、对业务成本高的错误和集中出现的错误；随机抽样用于发现意外模式。
- 每个结论标注证据等级：观测到的事实、合理假设、待验证因果解释；相关性不能直接支持干预结论。
- 将下一步写成可证伪假设，例如“字段 A 的采集延迟导致晚间样本召回下降；补充时间戳并按时间切分后验证”。
- 检查数据漂移、标签延迟、反馈回路和运行失败路径；即使不部署，也应在报告中说明。

### 1.3.5 章节实作：问题定义包

使用阶段 0 的公开表格数据项目，或 UCI Adult、Titanic 等公开数据，完成以下内容：

1. **问题说明**：一个段落定义预测对象、预测时点、输出、使用者和行动。
2. **数据卡与数据字典**：来源、许可、字段、缺失、敏感字段和已知局限。
3. **切分设计**：说明选择随机/分层/分组/时间切分的原因，并在代码中固定索引或 seed。
4. **指标契约**：主指标、约束指标、混淆矩阵工作点、基线和阈值选择方法。
5. **最小 Pipeline**：预处理仅在训练数据上 `fit`；实现 dummy 与逻辑回归/简单树基线。
6. **评估报告**：验证集选择过程、最终测试结果、bootstrap 区间或等价不确定性说明、错误样本分析。
7. **复现说明**：运行命令、依赖、配置、随机种子、数据获取方式与不应使用的场景。

### 1.3.6 章节练习与验收

1. 故意在 split 前标准化或编码，记录指标变化，解释为何这是泄漏。
2. 对至少一个随机切分和一个符合业务时序/群组的切分比较结果，说明哪个更可信。
3. 对 dummy、逻辑回归和树模型完成同一组评估表；结论必须包含复杂度和误差分布，不能只比较单一最高分。
4. 选取 10 个错误样本，写出数据错误、边界样本、标签噪声、特征不足和分布差异五类可能根因中的适用项。

**验收**：陌生读者仅凭 README 和配置即可重跑 baseline，且能在 5 分钟内知道任务目标、标签、切分、指标、最优模型并不代表的内容。通过后进入阶段 2，从线性回归开始系统学习监督模型。

## 与阶段 2 的衔接

阶段 2 的每一章都沿用本阶段的问题定义包：线性回归与逻辑回归首先在既定的切分和指标契约下建立基线；kNN、SVM、决策树和集成学习只在同一数据边界内比较。任何“分数提升”都必须同时回答：提升是否超过不确定性范围、牺牲了哪种错误、是否增加工程成本、是否在关键分组中退化。
